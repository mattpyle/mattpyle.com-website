The changelog feed carries one summary that mentions the address "`/writing/<slug>.md`". The feed wrote it as "`/writing/&lt;slug&gt;.md`". An RSS item description is escaped HTML, and a feed reader decodes it once. It then read "`<slug>`" as an unknown, unclosed HTML tag. The visible text became "/writing/.md".

A subscriber reading the entry about raw markdown post variants got a broken sentence about the very feature it announced. The W3C Feed Validator flagged this item as invalid HTML. It was the feed's only warning. The same summary on /changelog looked right, because the HTML page escapes it once.

The feed now escapes the ampersand and the angle brackets in each summary before it writes the description. The description reads "`/writing/&amp;lt;slug&amp;gt;.md`", which a feed reader decodes to the text "`/writing/<slug>.md`". The old form is gone from the feed.
