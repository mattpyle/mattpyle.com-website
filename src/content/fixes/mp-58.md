Every section page of the site sends a Link header that points to its markdown version. The three posts and the 13 changelog entries did not. None of those 16 pages sent one. Their HTML head did carry the alternate link, so an agent that parsed the HTML found the markdown. An agent that read only headers, for example from a HEAD request, did not.

The posts are the content an agent is most likely to be sent to summarise or cite. The site's own story is that every page has a markdown twin and says so.

The Link headers lived in a hand-written list, one rule per section path. Pages built from a slug never got a rule. The fix adds the header in the edge middleware, which already sees these routes. It points each post and entry at its own markdown address.

A post such as /writing/hello-world/ now answers with a header that names /writing/hello-world.md. Changelog entries do the same.
