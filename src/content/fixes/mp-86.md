The audit tool shares one hourly run per site. That run was keyed on the site's origin alone. The first page a caller named in the hour decided the page row for every later caller.

Three calls to audit_site within one minute named the WebMCP post, then the About page, then the bare origin. All three got the same report. Each carried a "named page" row measuring the WebMCP post. The About page was never fetched. The caller who named only the origin received a page row the docs say exists only when a page is named.

Someone auditing their own site relies on that row to learn how much of one page is content. A wrong page measured under "the named page" is worse than no row.

The fix keys the shared run on the origin plus the named page path. A caller naming the About page now shares only with others naming it. An origin-only call shares only with origin-only calls, so it gets no page row.

Three calls in one minute now return three separate runs. Each report measures the page its call named.
