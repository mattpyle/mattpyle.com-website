The site's A2A agent at `/a2a` listed the site's agent surfaces when asked. Its line about itself read "SendMessage, and GetTask for polling a deep audit's Task." It named neither CancelTask nor the audit consultant, which had been added on 13 November. The same endpoint's GET reply listed three methods and three skills. Its error text also named three methods.

This let down an agent that asked the A2A agent what it could do. The answer did not match the endpoint. An agent that believed it would not learn that a consultant session could be closed.

The change that added the consultant updated the Agent Card, agents.md and llms.txt. It missed one line in `scripts/generate-a2a-digest.mjs`. The fix rewrote that line. The new line named SendMessage, GetTask for polling a Task, and CancelTask for closing a consultant session.

After the deploy, the A2A agent's description of its own endpoint named CancelTask. That matched its GET reply and its error text.
