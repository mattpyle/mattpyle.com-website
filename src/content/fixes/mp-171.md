On every post, the header's "writing" link was marked `aria-current="page"`. On every changelog entry, the "changelog" link carried the same mark. Each page held it twice, once in the wide navigation and once in the narrow one. A screen reader read the link as "writing, current page, link", though the visitor was on a post, not on /writing/.

This let down screen-reader users who move through the header by link to learn where they are. The header is the one landmark they hear on every page, so the wrong place was announced on every post. Sighted visitors were not affected. The underline showing the section was right.

The header matched a link to the current page by prefix, so any page under /writing/ counted as /writing/ itself. The header now marks a link `aria-current="page"` only when the path is exactly that link's address. A section link on a child page is marked `aria-current="true"`, the current item in a set. The underline styles now match either value, so the section underline still shows on posts in both appearances.

Posts and changelog entries now carry `aria-current="page"` nowhere in their header. /writing/ and /changelog/ keep it, because there it names the page being shown.
