Every copyable snippet on /webmcp called executeTool with the arguments as a JSON string. There were six. The same call appeared in the WebMCP post, in the site's agent skill and in llms-full.txt.

The WebMCP specification changed in August 2026 to accept a plain object instead. Chrome followed in version 155. On current Chrome, a string argument is rejected. The page told readers the opposite: that an object throws "Failed to parse input arguments".

A developer judging whether to copy the experiment would paste a snippet and watch it fail. An agent that read the skill or llms-full.txt would learn the wrong call shape.

The snippets and the prose on /webmcp and in the post had already been corrected. This change removed the last quoted error from the agent skill. It now says that Chrome 154 and earlier took a JSON string and rejected an object.

The four places that carried the old snippet no longer hold it. The quoted error is gone from /webmcp and from the skill.
