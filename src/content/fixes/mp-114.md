The calling-convention block of agents.md gave the example executeTool(tool, '{}'). It then said the second argument is a JSON string, and that an object throws "Failed to parse input arguments".

That is the opposite of what Chrome 155 and later do. The WebMCP page, the how-to post, llms-full.txt and the site's skill all said the argument is a plain object. Only agents.md, which is hand-written, kept the old rule.

An in-browser agent that followed it got a TypeError on every tool call, with no reason to suspect the page. agents.md is the file the homepage and About page send agents to first.

The block now shows executeTool(tool, {}) and says the second argument is a plain object. It notes that Chrome 154 and earlier did the reverse. Its heading no longer cites a Chrome 150 measurement.
