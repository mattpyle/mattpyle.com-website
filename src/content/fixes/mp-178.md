The Steward page and agents.md both said that reading back an audit with `get_audit` is free. The page's rate-limit table listed six caps, for fast audits, deep audits and consultant sessions. It had no row for reads. Yet the MCP endpoint lets one caller make 60 reads a minute. It refuses the 61st with an HTTP 429 and a `Retry-After` header.

This let down a developer deciding whether to build a client against the endpoint. They read the table to learn what a polling loop may do. The page says it renders the caps the deployment enforces, and agents.md sends agents there for the numbers. A client built from either would not expect the refusal.

The sentence on the Steward page and in agents.md now says reads spend no audit allowance. They also fetch nothing at anybody's origin. It adds that reads are capped per caller per minute, shared by the MCP and A2A endpoints. The table gains a seventh row for reads. That row is built from the same settings the limiter uses.

On production, neither page calls `get_audit` free. The Steward table shows a read cap of 60 per caller per minute. The limit itself is unchanged.
