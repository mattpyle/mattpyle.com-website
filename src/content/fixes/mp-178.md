The `/steward` page and `/agents.md` both said `get_audit` is free. The endpoint at `/mcp` did limit it. One caller could read 60 times in a minute. The 61st read and every later one got an HTTP 429 with a `Retry-After` header. The rate-limit table on `/steward` listed six caps and had no row for reads.

This let down developers deciding whether to build a client against `/mcp`. They read the table to learn how fast a polling loop may run. The page says it shows the caps this deployment enforces. A polling client written from it would meet a refusal it was never told about. An agent reading `/agents.md` was sent to that same table for the numbers.

The table on `/steward` now has a seventh row: `Read (get_audit)`, per caller, 60, one minute. It is built from the same settings the limiter uses. The sentence on `/steward` and in `/agents.md` now says `get_audit` spends no audit allowance and fetches nothing at anybody's origin. It adds that reads are capped per caller per minute, shared by `/mcp` and `/a2a`. The limiter itself is unchanged.

On production, neither page calls `get_audit` free. The `/steward` table shows the read cap of 60, so a caller meets the 429 the page describes.
